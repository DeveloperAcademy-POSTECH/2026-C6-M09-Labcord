# Agent Rules·Skills 프로젝트 맥락

현재 의존성은 [Package.resolved](../../Researchers.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved),
모듈 구성은 [Package.swift](../../Packages/ResearchersModules/Package.swift)를 확인합니다.

## 현재 구현과 적용 기준

| 항목 | 현재 설정·적용 |
| --- | --- |
| Watch 앱 경로 | 소스는 `ResearchWatchApp/`, 스킴은 `ResearchWatch Watch App` |
| 로컬 패키지 | 단일 `Packages/ResearchersModules/Package.swift` 아래 네 개 타깃 |
| 기기별 저장·통신 | 기기별 구현은 `LabcordiOS`·`LabcordWatchOS`에도 있음. 새 저장 구현의 경로는 해당 작업에서 팀과 확인 |
| SwiftData | `LabcordShared/Models`의 모델 선언과 iPhone의 저장 실행 책임을 구분. Watch에 저장 구현을 새로 두거나 기존 모델을 자동 이동하지 않음 |
| iPhone·Watch 화면 | iPhone 실행과 Debug 데이터 초기화마다 새 epoch를 발행하고, 목록·화면·실험·기록의 revision은 해당 epoch 안에서 비교. Watch의 화면 이동은 iPhone의 현재 화면 버전을 확인한 뒤 반영하며 녹음·저장 미확정·편집 초안은 보호 |
| Watch 실험 시작·결과 | Watch 시작 요청은 20초 동안 유효. 이미 전송한 요청은 일시 비활성화에 유지하고 화면을 닫으면 취소. 홈에서는 미저장 Watch 녹음을 유지한 상태로 같은 실험을 열 수 있음. Watch가 진행 중인 실험에 들어오면 실행 중인 iPhone 앱도 저장 상태를 확인하고 그 실험으로 이동. 같은 실험에서 Watch가 다시 활성화되면 화면은 동기화하고 연결 안내는 반복하지 않음. iPhone은 저장 직전 취소·만료를 확인하고, 진입을 저장한 뒤 요청 ID로 응답. 준비 중 해당 요청을 취소하면 기존 실험 이력을 보존. 결과 화면이 사라지면 Watch에서 닫거나 iPhone 화면을 다시 조회할 수 있음 |
| Watch 실험 목록 | 조회 응답의 목록을 화면에 바로 반영합니다. iPhone 백그라운드 목록 응답은 최대 10초 기다리고 실패하면 다시 시도할 수 있습니다. |
| iPhone 홈 실험 목록 | 조회 수명은 목록 Feature가 관리합니다. 화면 task의 취소를 조회에 연결하거나 중복 조회끼리 취소하지 않고, 최신 요청 revision의 응답만 반영합니다. 화면 이동과 삭제에서 보내는 명시적 취소는 유지합니다. |
| 실험 결과 필터 | 일반 글자 크기는 기존 가로 배치를 유지합니다. 접근성 글자 크기에서는 유형·정렬 선택을 가로로 스크롤해 모든 항목에 접근할 수 있습니다. |
| Watch 실험 타이머 정보 | Watch 실험 화면은 해당 실험의 `WatchExperimentSnapshot`을 요청·구독하고, `mode`를 타이머 페이지에 표시. 프로토콜 타이머 시간과 진행 중인 타이머 배열도 snapshot에 포함 |
| 타이머 Live Activity | 세션에서 홈으로 나가면 실행 중인 타이머를 동기화. iPhone·Watch에서 실험 종료를 저장하면 같은 실험의 앞선 동기화가 끝난 뒤 타이머 Activity를 모두 종료 |
| iPhone 사진 촬영 | 버튼과 제스처는 같은 카메라 경로로 촬영합니다. 프리뷰와 사진 촬영 세션에는 마이크 입력을 연결하지 않습니다. 영상 시작 시에만 마이크를 연결하고 종료·실패·취소 처리 후 분리합니다. 사진·영상 시작 직전에 실제 카메라 세션 상태를 확인하고 일시적인 중단에서 복구되기를 짧게 기다립니다. 권한 거부와 세션 사용 불가를 구분합니다. iPhone 디버깅 메뉴의 사진 셔터음 설정은 iPhone과 Watch의 사진 요청에 적용되며, 지원 기기에서는 시스템 셔터음 억제를 적용합니다. Debug 빌드에서 무음 설정을 켰고 기기가 셔터음 억제를 지원하지 않으면 다음 영상 프레임을 JPEG로 저장합니다. |
| Watch 사진 촬영 | 버튼이나 사진 단축어를 한 번 실행하면 촬영 요청 하나를 시작합니다. 단축어가 Watch 화면을 잠시 가려도 같은 요청으로 저장을 이어갑니다. iPhone이 촬영을 예약하면 Watch의 실험 화면이나 사진 시트가 같은 종료 시각으로 남은 초를 표시합니다. 즉시 촬영에는 카운트다운이 없습니다. iPhone의 손동작 인식이 끊겨도 Watch의 카운트다운은 계속됩니다. 촬영 시점에 카메라를 사용할 수 없으면 실패를 알리고, 이미 촬영한 사진은 저장 확인까지 보관합니다. |
| iPhone 영상 제스처 | 세 손가락 제스처로 녹화를 시작합니다. 5초 녹화가 끝나기 전에 같은 제스처를 다시 인식하면 정지합니다. 시작 처리 중에 인식한 정지는 녹화가 시작되는 즉시 적용합니다. |
| Watch 영상 제스처 | 영상 단축어를 다시 실행하면 iPhone 전송 전에는 녹화 준비를 취소합니다. 시작 명령을 보낸 뒤에는 같은 녹화 ID의 시작이 확인되는 즉시 정지하고, 이미 녹화 중이면 바로 정지해 저장을 확인합니다. 3초 안에 정지를 확인하지 못하면 이전 녹화 ID로 다시 확인하거나 화면을 닫을 수 있습니다. |
| Watch 녹음 종료 피드백 | 음성 제스처로 기록을 열면 새 녹음을 시작합니다. 화면 버튼은 이전 미완료 녹음을 복구할 수 있습니다. 종료하면 전송 화면으로 전환하며, 완료 버튼을 눌렀을 때는 마이크 입력을 닫은 뒤 앱의 종료 햅틱을 재생합니다. 제스처 종료는 단축어의 시스템 피드백을 사용합니다. |
| Watch 음성 전송률 | iPhone이 수신 확인한 고유 PCM 샘플의 비율을 표시합니다. 전송량을 확인 중일 때와 전사·저장 단계에는 각각의 상태를 표시합니다. 전송 또는 iPhone 처리를 기다리는 중에 Watch가 다시 활성화되면 진행 상태를 다시 확인합니다. |
| Watch 녹음 표시 | iPhone 앱 상단에 기존 녹음 카드로 Apple Watch 녹음 상태를 표시. 녹음이 끝나거나 마지막 상태의 유효 시간이 지나면 숨기고 iPhone의 녹음·녹화 카드가 우선 |
| Watch 녹음 오디오 | 새 Watch 녹음은 16 kHz 모노 signed 16-bit little-endian PCM으로 변환해 v1 형식으로 보관·전송. iPhone은 녹음 헤더의 샘플레이트로 저장·재생하고, 전사 입력은 기기의 SpeechAnalyzer와 언어 모델이 지원하는 포맷에 맞춤 |
| Watch 연결 복구 | 세션 활성화·설치 인식·도달 가능성을 구분해 기록합니다. 복구 시 현재 화면·실험·목록과 현재 실험 기록을 다시 게시합니다. 백그라운드 전송의 큐·완료·실패는 전송 ID로 연결하며, 완료 콜백은 iPhone 저장 확인과 별개입니다. |
| Watch 복구 저장소 | 기존 `requests.json`을 읽고 새 저널 변경은 요청별 원자적 파일에 기록합니다. 오디오 청크의 검증된 샘플 범위만 메모리에 재사용하며, 정리와 저장 증명은 디스크의 원본을 검증합니다. |
| 기록 표시와 저장 | 상대 기기의 화면 표시는 원본 처리에 사용하지 않음. Watch 녹음 화면을 닫아도 원본을 보존하며 다시 열면 같은 ID로 전송·저장을 재개. iPhone에 저장한 PCM과 일치하는 응답이나 명시적 취소 확정까지 해당 실험의 나가기·종료를 보류. Watch 원본 정리는 저장 파일 검증을 거친 뒤 진행하며, 종료된 기록의 표시 시간은 고정. iPhone 음성 시작 거부·빈 전사·중지 실패도 현재 녹음 ID에 해당하는 경우 실패 상태를 게시하고, 취소 완료와 오래된 응답을 구분 |
| 기록 입력과 실험 종료 | 진행 중인 Watch 녹음 중에는 iPhone에서 새 기록 시작을 기다립니다. 전송·전사·저장 대기 중에는 새 기록을 시작할 수 있습니다. iPhone에서 실험을 종료할 때 미저장 Watch 녹음이 남아 있으면 이유를 표시하고, 전사 검토가 준비된 녹음은 사용자가 저장을 선택할 수 있습니다. |
| 기록·단축어 실패 처리 | Watch에 녹화 시작 시각이 오기 전에는 대기를 표시하고, 정지를 누르면 즉시 로컬 실패를 표시합니다. Watch 영상의 저장 대기 원본은 iPhone 카메라 화면이 잠시 사라져도 유지합니다. 영상 저장 대상이 확인되지 않으면 Watch에 다시 촬영을, 저장 결과가 불명확하면 같은 ID로 재시도를 제공합니다. 전사가 일시 실패하면 iPhone이 한 번 다시 시도합니다. Watch 음성 기록 실패 화면에서 이전 기록을 재시도하거나, 원본은 보존한 채 새 ID로 녹음을 시작할 수 있습니다. 음성 버튼이나 단축어를 한 번 실행하면 해당 녹음 상태를 시트가 닫힐 때까지 공유합니다. 화면을 다시 그려도 녹음을 추가로 시작하지 않습니다. 음성 화면을 닫은 직후 2초 동안 반복된 음성 단축어는 새 녹음을 열지 않습니다. 단축어는 실행 준비부터 Watch 응답까지 최대 3초를 기다리고, 전송·응답 오류는 요청 ID와 오류 코드로 추적합니다. iPhone에서 만든 음성·사진·영상 단축어의 동작 식별자도 Watch 앱에 등록합니다. Watch에서 실행된 동작은 최대 3초 동안 실험 화면이 준비되기를 기다린 뒤 해당 화면에서 한 번 처리합니다. 사진·영상 시작 직후 iPhone 연결이 준비 중이면 최대 3초 동안 상태 조회를 다시 시도하며 촬영 시작 명령은 한 번 보냅니다. Watch Debug 빌드는 단축어 수신 경로와 처리 여부를 최대 64 KB의 로컬 진단 로그에 남깁니다. |
| Watch 기록 화면과 타이머 | 기록 화면 제목은 한 줄로 표시하고 길면 끝을 줄임표로 표시합니다. Watch에서 목록으로 돌아갈 때 이전 iPhone 화면으로 인한 자동 재진입을 차단합니다. 타이머 목록에서 스와이프 삭제 버튼은 일시정지한 한 행씩 열리고, 제스처가 취소되면 임시 이동값을 초기화합니다. |
| Watch 사진·영상 명령 | iPhone은 실험·기록 ID·종류·revision과 중복을 확인한 뒤 실행합니다. 현재 iPhone에 열린 실험과 일치하는 요청은 다른 진행 중 실험이 저장돼 있어도 허용하며, 다른 실험 화면이나 revision 불일치는 계속 거절합니다. 화면의 명령 완료 대기는 10초이고, 만료돼도 처리 중이거나 저장 대상인 원본은 그대로 둡니다. Watch는 미확정 기록의 ID를 보관해 재연결·재실행 때 조회합니다. 저장된 기록의 취소 요청은 저장 상태와 취소 거부를 함께 반환합니다. |
| 들여쓰기 | 스타일 가이드는 2 spaces, 기존 Swift는 주로 4 spaces. 적용 기준은 팀 확인 사항이며 일괄 포맷 변경하지 않음 |
| import 배치 | 스타일 가이드와 기존 코드 배치에 차이가 있음. `.swiftlint.yml`의 `sorted_imports`도 확인하며 새 우선순위를 임의 확정하지 않음 |
| 줄 길이 | warning 99·error 150이고 `--strict`는 warning도 실패 처리 |
| 도구·SDK | Package의 iOS/watchOS 최소 26, 프로젝트 배포 대상 27.0, CI runner `xcode-27`, Swift tools 6.4 |
| TCA API | 잠긴 버전은 1.26.2. 사용하는 API의 지원 여부를 확인 |
| 제스처 연습 애니메이션 | iPhone 앱이 Lottie 4.6.1로 Watch 제스처 JSON을 재생. iPhone 제스처 세 개를 완료하면 같은 화면의 Apple Watch 연습 탭으로 이동합니다. iPhone의 Watch 연습 탭에서 받은 단축어는 해당 카드의 인식 결과만 표시합니다. Watch 앱을 처음 열 때는 제스처 전에 열려 있던 iPhone 실험을 최대 3초 동안 확인합니다. 같은 실험 안에서 타이머나 기록 상태가 바뀌어도 요청을 이어가며, 실험에서 나갔다가 다시 들어오면 이전 요청은 만료됩니다. Watch 목록에서의 재진입 충돌은 iPhone이 최종 판단하며, 현재 iPhone에 표시된 진행 중 실험으로 돌아가는 요청은 다른 진행 중 실험이 저장돼 있어도 허용합니다. |
| 최초 홈 제스처 안내 | 온보딩을 마친 신규 사용자는 연습 화면이 준비될 때까지 물음표 안내로 진입 |
| 실험 권한·설정 복귀 | 권한 확인과 alert 문구, 설정 복귀 ID 저장은 `LabcordiOS/Permissions`가 담당. iPhone 화면 복귀 경로와 준비 overlay는 `Researchers`가 담당 |
| 음성 인식 용어 힌트 | iPhone과 Watch 녹음 전사에 프로토콜 추출 용어, 단위 힌트, 공통 연구 용어를 우선순위 순으로 합쳐 중복을 제거하고 최대 100개를 전달. 별도 사용자 지정 언어 모델의 가중치는 0.3 |
| 프로토콜 분석 결과 용어 | 카테고리별 수동 추가는 20개 미만일 때 가능. 이미 20개 이상인 분석·기존 결과는 보존하고 삭제해 20개 미만이 되면 다시 추가 가능 |
| 프로토콜 분석 중단 | 미완료 결과 화면에 부분 결과와 등록 시 분석 종료를 안내. 뒤로 가면 화면의 편집은 버리고 분석 화면에서 재시도 가능. 실행 오류는 문서 내용 없이 오류 도메인·코드와 진행 단계를 기록 |
