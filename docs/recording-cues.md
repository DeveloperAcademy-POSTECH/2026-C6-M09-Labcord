# 녹화 진행 큐

`scripts/recording-demo-cues.sh`는 내레이션 순서대로 촬영자에게 진행 큐를 보여 준다. 각 장면은 Enter로 진행하므로 촬영과 대사에 필요한 시간을 충분히 확보할 수 있다. iPhone의 실험 화면에서 `타이머` 접근성 텍스트를 최대 45초 동안 확인한다. 그 외 조작과 저장 결과는 촬영자가 직접 확인한다. 테스트 전체가 자동으로 통과했다는 뜻은 아니다.

```sh
# 장치 조작 없이 순서 확인
bash scripts/recording-demo-cues.sh --dry-run

# device_open으로 iPhone을 연 뒤 반환받은 agent-device로 DEBUG 앱을 실행한다.
'/반환받은/agent-device' open com.researchers.Researchers
LABCORD_AGENT_DEVICE='/반환받은/agent-device' bash scripts/recording-demo-cues.sh
```

이번 촬영은 iPhone 화면만 사용한다. PDF, 배경 영상, 시연 결과 자산을 준비한다. Debug 시뮬레이터 앱은 기본 실행 시 기존 실험과 관련 미디어를 삭제한다. 기존 촬영 데이터를 유지하려면 먼저 백업하고 `-LabcordPreserveSimulatorExperiments` 실행 인수로 시작한다. 이 인수는 시작 시 실험 초기화를 건너뛴다. 새 촬영 세션을 초기화해 시작할 때는 보존 인수를 생략하고 홈이 비었는지 확인한 뒤 실험을 등록한다. 결과 화면 촬영 직전에 홈에서 숨겨진 `시연 결과 준비` 접근성 버튼을 누르고 `시연 결과 준비 완료`를 확인한 뒤 최근 실험에서 결과를 연다. 이 순서의 전체 런타임 검증은 아직 필요하다. 중단하려면 Ctrl-C를 누른다.

시뮬레이터는 배경 영상 속 손동작을 인식하지 않는다. V03·V04·V05는 재생 기준 시점에 iPhone 기록 동작을 실행한다. V06-A·V07·V08도 Watch 장면용으로 같은 iPhone 음성·사진·영상 화면을 연출하며 Watch 연결은 필요하지 않다. 이는 촬영 연출이며 실제 Watch 제스처 인식이나 기기 간 연결을 검증한 결과가 아니다.

촬영 화면의 영상 선택과 시연 결과 준비 진입 버튼은 보이지 않는다. 자동화 도구에서 접근성 버튼 `영상 선택`, `시연 결과 준비`로 조작한다. 영상을 선택하면 선택 화면이 닫힌다.

전체 큐의 연속 촬영과 V06-A·V07·V08의 iPhone 동작 및 실제 반응 지연은 별도 검증이 필요하다. 타이머와 결과 화면은 장면마다 실제 표시와 상태를 확인한다. Watch 화면과 통신은 이번 촬영 범위에 포함하지 않는다.

V12는 프로토콜 실험의 설정된 타이머 탭에서 첫 타이머를 시작한다. 시작할 수 없는 상태에서는 오류가 표시된다. iPhone 시뮬레이터에서 5분 타이머가 실행되는 것을 확인했으며, 손가락 접촉과 앱 반응의 프레임 차이는 측정하지 않았다.

2026-11-18 교체본은 `Documents/LabcordDemoVideos/W02_double_pinch.mp4`로 적용한다. 기존 `V06-A 재생` 버튼은 이 새 파일을 선택하며, 파일이 없으면 비활성화된다. 새 파일은 24fps·193프레임·8.041667초다. 두 번째 핀치 해제 기준인 25프레임 / 1.041667초에 음성 기록을 한 번 요청한다. 위 표의 이전 A+B 합본은 보관용으로 남기며 현재 버튼에서 재생하지 않는다.

- V03은 항상 “A01, pH 4.04 확인.”으로 시작하는 첫 번째 대본 3문장이다.
- Watch 음성 장면은 항상 “A01, 5분 경과.”로 시작하는 두 번째 대본 2문장이다. 녹음 중에는 전사를 내보내지 않고 종료 후 최종 전사에 반영한다. 세 번째 문장은 없다.

- 영상이 일시정지되면 미디어 시각이 멈추므로 이후 문장을 먼저 표시하지 않는다. 녹음 준비가 늦어 이미 지난 문장은 한 번씩 따라잡고, 다음 문장은 해당 영상 시각을 기다린다.
- 현재 장면의 녹음을 취소하거나 다시 촬영해도 대본 순번이 바뀌지 않는다. 촬영용 영상이 없는 수동 녹음만 기존 회차별 대본과 +1/+5/+9초 규칙을 유지한다.

이 변경은 `DEBUG && targetEnvironment(simulator)` 촬영용 코드에 한정된다. 실제 음성 인식이나 Watch 통신 검증을 대신하지 않는다. W01~W05는 비율을 유지하면서 카메라 화면을 채우므로 영상 가장자리가 잘릴 수 있다. Debug 앱의 보존 인수 없는 실행은 기존 실험 자료를 초기화하므로, 실제 사용 중인 시뮬레이터를 재시작하기 전에는 자료를 백업하고 보존 인수를 지정한다.
