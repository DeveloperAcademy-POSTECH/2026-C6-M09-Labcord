# Entry 검증 기록

2026-10-28의 홈·프로토콜 없는 실험 등록 구현을 검증했습니다.
기능 검증과 Figma 화면 비교는 별도로 판단합니다. 아래 픽셀 차이는0이 아니므로
완전한 화면 일치가 완료됐다는 뜻이 아닙니다.

## 환경과 범위

- Xcode27.1 (`27A9275`), Swift6.4, SwiftLint0.65.1.
- iOS27.0의 전용 iPhone17 시뮬레이터, 402×874pt·scale3.
- 실제 제품 대상은 `Researchers`, bundle ID는 `com.researchers.Researchers`입니다.
- 별도 QA 호스트는 실제 Entry 소스·리소스를 참조하며 제품 앱에는 fixture·검증 플래그가 없습니다.
- 물리 기기를 사용하지 않았습니다. 공유 모델·패키지 의존성·Watch 통신을 변경하지 않았으므로
  Watch 빌드·연결 검증은 이번 변경의 대상으로 선택하지 않았습니다.

## 화면 검수 기준

2026-10-28 후속 사용자 요청에 따라 기본 SwiftUI `Text`와 시스템 기본 폰트를 사용합니다.
기존 `EntryTextRenderer`와 Noto 폰트·자간·베이스라인 보정을 제거했습니다.
OS 글자 렌더링 차이를 허용하며, 폰트 변경에 따른 윤곽·문자열 폭 차이도 구분합니다.
별도 글자 윤곽 렌더러·A8 마스크 생성·계산 캐시는 제품에 넣지 않습니다.
문자열·폰트 매핑·크기·자간·행높이·배치·줄임표·접근성과 화면 이동·저장 동작은 계속 검수 대상입니다.
버튼·카드·아이콘·그림자 차이를 모두 글자 렌더링 차이로 간주하지 않습니다.

아래 전체 RGB 비교는 이 결정 뒤에도 같은 원본과 계산 기준을 사용합니다.
허용한 차이를 지우거나 마스킹해 픽셀 일치0으로 표시하지 않으며, 외부 시제품의 더 낮은
오차를 제품 결과로 대체하지 않습니다. 아래35차 수치는 **기본 폰트 변경 전의 이력**입니다.
현재 폰트 정책은 [폰트 안내](entry-fonts.md)를 따릅니다.

실제 제품 앱 스모크는 검증용 client나 launch argument를 주입하지 않고 제품 bundle ID로 실행했습니다.
첫 실행에서 UUID 집합은 `0 → 취소 후0 → 저장 후1 → 재실행 후 동일1`이었습니다.
새 행의 제목 `새 실험`과 상태 `준비`도 확인했습니다. 최신 제품 빌드의 두 번째 실행에서는
기존 실험1개를 유지한 채 `1 → 취소 후1 → 저장 후2 → 재실행 후 동일2`를 확인했습니다.
기존 UUID가 빠지거나 바뀌지 않고 새 UUID가 정확히 하나만 추가됐습니다.
원본 `Experiment` 전체를 직접 읽거나 후속 실험 화면의 연결까지 검증한 결과도 아닙니다.
실제 제품 저장 스모크는 `200b4d2`의 26차 표시 빌드에서 실행했습니다.
원주 반사광을 적용한 30차 제품 빌드도 기존2개를 유지한 채 홈·등록·취소 UI 테스트가 통과했습니다.

테스트 도중 시뮬레이터 서버 종료(`Mach -308`)로 실행 전 실패한 회차가 있었습니다.
해당 전용 시뮬레이터만 다시 부팅한 후 전체14개가 통과했습니다.
제품 스모크의 최초 명령은 Xcode가 `-test-iterations 1` 인수를 거부해 앱 실행 전에 실패했습니다.
옵션을 제거하고 새 결과 경로에서 실제 테스트1개가 통과한 결과를 위 표에 반영했습니다.
색상 보간을 명시하는 과정의 opaque 반환형 추론 오류는 `AnyShapeStyle`로 타입을 지정해 수정했고,
이후 해당 화면 UI 테스트가 통과했습니다.
실패한 로그·xcresult도 보존하고 통과 결과와 구분했습니다.

## 원본과 전체 화면 비교

기준은 Figma 파일 `v6cxQ2I6zURWYQaG5pnuBL`의 원본 프레임을 scale3으로 내보낸 PNG입니다.
최신 디자인 페이지를 수정하지 않았습니다.
같은 날06:24KST에 두 프레임을 다시 내보내 SHA256이 아래 기준과 그대로 같음을 확인했습니다.

| 화면 | Figma node | 원본 PNG SHA256 |
| --- | --- | --- |
| 홈 | `502:12299` | `b8a7cf1d54c18c08dfeeea361ebe09f44649b0a42e0dfeb99197a673f0142762` |
| 등록 | `502:12563` | `93badfc7dfbe0c57886bc924e5d1e270478b5759375ed974028897a9a8892890` |

두 입력 모두1206×2622px입니다. 캡처는 XCTest가 얻은 전체 원시 화면이며,
리사이즈·좌표 정렬·마스크·차이 임계치·색상 변환을 적용하지 않습니다.
MAE는 모든 RGB 채널 절대 차이의 평균이며 범위는0…255입니다.
서로 다른 픽셀 비율은 RGB 중 한 채널이라도 다른 픽셀을 모두 셉니다.

제품의 26차 등록 캡처와 같은 소스의 QA 등록 캡처도 별도로 비교했습니다.
전체3,162,132px 중24px가 최대 채널 차이1/255로 달랐고 MAE는0.00000632485였습니다.
이 차이는 글자 AA 경계에 있었으며 배경·그림자·뒤로 가기는 같았습니다.
제품 캡처와 QA 캡처가 완전히 동일하다고 표시하지 않습니다.

30차 제품 화면 검증에서는 앱 캡처와 전체 화면 캡처가 각각 PNG 바이트까지 같았습니다.
실제 제품 등록과 QA30 등록 사이에는18px가 최대 채널 차이1/255로 달랐고,
MAE는0.00000569236이었습니다. 실제 제품의 설정·추가·표면·반사광을 포함한 고정6개 ROI는
QA30과 같았습니다. 이 ROI는 제품/QA 표시를 진단한 값이며 전체 화면 일치 판정을 대신하지 않습니다.
실제 홈에는 저장된2개, 고정 fixture에는7개가 있으므로 둘의 홈 전체를 일치 비교하지 않았습니다.
일반 실행 직후 `simctl` 캡처에만 나타난 좌상단4×4px의 일시적인 조각도 원본 파일로 보존했습니다.
후속 앱·전체 화면 캡처에서는 그 영역이 순백이었으며, 캡처를 수정해서 지우지 않았습니다.

34차 제품 빌드·설치 후의 화면·취소 검증도24.290초에 통과했습니다.
기존 UUID2개가 그대로 유지됐고 새 실험은 생성하지 않았습니다. 앱·전체 화면 캡처는
두 화면 모두 PNG 바이트까지 같았습니다. 제품 등록↔QA34의 차이는18px·최대1/255·
MAE0.00000569236이며, 제품 홈의 동일6개 진단 ROI는 QA34와 같았습니다.
제품 등록↔Figma 전체는53,546px가 다르고 MAE0.057533757입니다.
목적 기기에 맞춘 실제 asset catalog에는 사전 생성 아이콘3개의3x template 자원이 포함됐고,
폰트2개와 OFL의 SHA256도 원본과 같았습니다. 이 제품 검증도 홈 전체의 일치 판정을 대신하지 않습니다.

35차 제품에서도 같은 화면·취소 테스트가24.318초에 통과했습니다. UUID2개를 그대로 유지했고,
앱·전체 화면의 두 PNG가 각각 바이트까지 같았습니다. 등록의 QA35 대비18px·최대1/255 차이와
Figma 대비 MAE0.057533757은34차와 같고, 기존 홈6개 진단 ROI도 QA35와 같았습니다.
실제 홈2개 행의 화살표 core는 각각155px가 기대 색 `(138,138,142)`와 일치했습니다.
이 두 행의 위치를7개 fixture 행과 일치 판정하지 않았습니다. 제품 catalog에는 화살표까지
4종3x template 자원이 포함됐고, 폰트·OFL의 원본 SHA도 유지됐습니다.

| --- | ---: | ---: | ---: |
| 홈 | 113,877 / 3,162,132 | 3.60127281% | 0.086975180 |
| 등록 | 53,540 / 3,162,132 | 1.69316145% | 0.057529962 |

34차는 원본 SVG에서 사전 생성한 아이콘9개와 일반 알파 합성을 사용합니다.
해당 제품 소스를 참조하는 QA 호스트에서 단위10개·UI4개가 다시 통과했고, 두 캡처는
외부 자산 프로토타입과 PNG 바이트까지 같았습니다. 재현 도구를 전용 Simulator에서 실행한
출력9개도 제품 PNG와 바이트까지 같았습니다. 런타임 윤곽 계산 코드는 제품에 포함하지 않습니다.

35차는 행의 화살표도 같은 방식의 템플릿 자산으로 표시합니다. 화면 캡처가 외부 후보와
두 화면 모두 PNG 바이트까지 같았고, 화면·좌표·취소 및 행 선택·생성·재실행의 UI2개가 통과했습니다.
확장된 생성 도구를 전용 Simulator에서 다시 실행한 PNG12개도 제품 자산과 바이트까지 같았고,
기존 아이콘9개는 변경되지 않았습니다. 이전34차 전체 검증은 단위10개·UI4개 통과입니다.

원형 버튼과 하단 버튼의 접근성 프레임은 원본 좌표와 같습니다.
설정·추가는 각각 `(334,26,48,48)`, `(334,743,48,48)`이며,
뒤로 가기·프로토콜 없이 진행·다음은 각각 `(14,67,44,44)`,
`(16,740,370,44)`, `(16,784,370,50)`입니다.

한글 원본 윤곽·베이스라인·혼합 문자열과 아이콘 벡터의 출처는
[폰트 안내](entry-fonts.md), [아이콘 안내](entry-symbols.md)에 기록했습니다.
현재 남은 차이는 글자·벡터 가장자리의 raster coverage와 원형 버튼의 표면·그림자에 있습니다.
같은 glyph의 순수 CoreText 렌더에서도 일부 차이가 재현되므로 크기·굵기를 임의로 바꾸는
근거로 삼지 않습니다. 원본 PNG를 앱 UI로 붙이거나 비교 기준을 약하게 만들어 일치 처리하지 않습니다.

## 픽셀 지표 재현

Python 표준 라이브러리만으로 원본·캡처의 PNG CRC, 필터와 원시 채널을 읽을 수 있습니다.
8bit RGB/RGBA·비인터레이스·불투명 PNG를 지원하며, 크기가 다르면 오류를 반환합니다.

```sh
python3 scripts/verification/compare-entry-png.py \
  /외부/QA/figma-502-12299-3x.png \
  /외부/QA/home-35-3x.png \
  --output /외부/QA/home-comparison-new.json
```

기존 보고서는 덮지 않습니다. 종료 코드0은 분석 성공이며, 일치 여부는 보고서의
`pixelsIdentical`로 확인합니다. `false`를 픽셀 검증 통과로 읽지 않습니다.
원본·캡처 SHA256, 전체 픽셀 수·차이·MAE·최대 채널 차이·alpha 차이도 함께 남깁니다.
나란히 배치하거나 확대·축소한 시각 자료는 검토용이며 지표 계산 입력으로 사용하지 않습니다.

## 보존과 제한

로그·xcresult·원시 PNG·JSON·Mermaid SVG·도구 캐시는 저장소 밖의 해당 날짜 QA 폴더에 보존합니다.
첨부 대화 원문·개인정보와 검증 결과물은 앱 bundle이나 저장소에 포함하지 않았습니다.
[개인 포크 PR#33](https://github.com/hellosunghyun/2026-C6-M09-Researchers/pull/33)에서
임시로 사용한 Rules·Skills의 경로는 `.gitignore`로 제외했습니다.

코드·문서의 `git diff --check`는 통과했습니다. 기준 커밋 대비 전체 검사에는 OFL 원문의
21행 trailing whitespace 한 곳이 있습니다. 라이선스 바이트 보존을 위해 원문을 수정하지 않았고,
해당 파일을 제외한 검사와 [원본 SHA256 확인](entry-fonts.md)을 각각 수행했습니다.
