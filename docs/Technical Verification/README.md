## Watch 연결·실패 복구 검증 (2026-11-09)

Watch에서 저장·취소 요청을 보내기 전에 연결 또는 진행 중인 조회 때문에 거절됐다면,
미송신이고 보관된 요청·결정도 없음을 확인한 경우에만 화면의 결정 대기를 해제합니다.
음성 이벤트 스트림이 종료되면 로컬 원본의 완전성과 녹음 종료를 다시 확인합니다.
완전한 원본이 보관된 실패 기록은 원본과 결과 항목을 유지한 채 실패 화면을 닫고
새 녹음을 허용합니다. 부분·손상 원본과 이미 전송된 미확정 요청·취소는 계속 보호합니다.

임시 XCTest 하네스로 실제 소스를 참조해 iOS 27 시뮬레이터 50개,
watchOS 27 시뮬레이터 42개를 실행했습니다. 총 92개 통과, 실패·생략 0개입니다.
정상 응답, 미연결, 응답 유실·지연·중복·순서 역전, 재연결, 원본 복구,
미송신 결정과 단축어 재입력 경로를 포함합니다. 원격 응답은 주입한 값이며
실제 두 기기의 WCSession 교환이나 AssistiveTouch 검증은 아닙니다.
앱 양쪽 시뮬레이터 빌드와 전체 SwiftLint도 통과했습니다.

사진 단일 요청 후 오류와 음성 단축어 직후 실기기 크래시는 재현되지 않았습니다.
WatchConnectivity 콜백에는 `@Sendable`을 명시해 MainActor 문맥 상속을 막습니다.
iPhone 단축어는 실패 단계·상태 여부·요청 식별자를 진단 로그로 남기며
녹음·사진·전사 내용은 기록하지 않습니다. 실제 페어링 기기의 연결 단절·재연결,
화면 전환·제스처, 카메라·마이크와 크래시 보고서는 별도 검증이 필요합니다.


### 실기기 재현 후 보완 (2026-11-09)

BASERIZE 1.0(6)을 실제 iPhone·Watch에 설치한 뒤 음성 입력에서 처리 중 안내와
기록 상태 복구 오류가 재현됐습니다. 기존 보관 음성 한 건은 양쪽 저장 표시와
정리 증명까지 일치했으며, 새 음성 두 건은 오디오 구간 없이 취소됐습니다.
이 상태만으로 새 음성 취소의 직접 원인을 확정하지는 않습니다.

기록 구독마다 식별자를 부여해 이전 구독의 늦은 복구 완료·실패가 새 구독을
변경하지 못하게 합니다. 현재 구독 준비와 복구 성공 뒤 입력을 다시 허용하고,
먼저 도착한 리뷰 기록의 자동 저장 카운트다운도 재개합니다. 원본 보존·취소
작업 자체는 구독 변경으로 취소하지 않습니다.

Watch 자체 음성 단축어도 실제 `capturing` 상태를 확인한 뒤 접수를 반환합니다.
`starting` 상태의 기록 생성만으로 단축어를 완료하지 않습니다. 녹음 시작·복구
실패 로그에는 단계, 식별자, 오류 도메인·코드만 기록하고 원본 내용은 남기지 않습니다.

실제 Feature·IntentRuntime·Service 소스를 참조한 watchOS 27 XCTest 35개
(기존 22개와 추가 13개)가 통과했습니다. 구독 교체 뒤 늦은 성공·실패,
현재 복구 실패 후 성공, 종료된 구독, 백그라운드 원본 보존 작업,
리뷰 카운트다운 재개, 음성 시작 지연·실패·취소를 포함합니다.
새 캡처는 현재 구독 복구를 기존 준비 제한 시간까지 기다리며, 진행 중인 음성의
중지는 복구 완료를 기다리지 않습니다. 복구 중 앱 이탈은 새 캡처를 시작하지 않습니다.
시뮬레이터 결과는 실기기 단축어·제스처와 사진 단일 실행 성공을 대신하지 않습니다.
