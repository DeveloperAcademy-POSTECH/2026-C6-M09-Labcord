# 문서 파싱 코드 리뷰

이 문서는 1차 리뷰 시점의 기록이다. 이후 완료한 형식 보완과 최종 검증은
[보완 검증 기록](Completion-Verification.md)을 참고한다.

2026-10-21 기준으로 `Researchers/Services/DocumentParsing/`와 관련 XCTest 코드를
리뷰하고 수정했다. 기존 브랜치의 변경과 iOS 27.0 / Swift 언어 모드 5.0을 유지했다.
의존성과 UI 구조는 변경하지 않았다.

## 수정한 문제

| 우선순위 | 문제 | 수정 |
| --- | --- | --- |
| P1 | DOC·XLS·PPT에도 ZIP 검사를 적용해 백엔드 진입 전에 거절 | ZIP 컨테이너 검사 대상을 DOCX·XLSX·PPTX로 한정 |
| P1 | Office·HWP·참조 이미지의 OCR 블록에 같은 읽기 순서 부여 | 블록을 추가할 때 순서를 지정하고, 결과 생성 시 안정 정렬과 연속 순번 보장 |
| P1 | Markdown 표 내부 순번이 문서의 앞 블록과 충돌 | 표를 문서에 합칠 때 문서 기준 순번 적용 |
| P1 | 호출자 격리 설정에 따라 메인 액터에서 파싱할 가능성 | 공개 비동기 진입점에 `@concurrent` 적용 |
| P1 | 이미지 처리의 취소가 일반 실패 경고로 처리될 가능성 | OCR 전후·이미지 사이에 취소 확인, 취소 오류 전파 |
| P1 | 실패한 문서의 최종 진행 이벤트 누락 | `failed`·`cancelled` 단계 추가, 배치에서도 입력별 종료 이벤트 유지 |
| P1 | ZIP 앞부분의 본문 문자열을 실제 컨테이너 항목으로 오인 | 검증한 중앙 디렉터리의 항목 이름으로 판별, 식별 단계에도 자원 제한 적용 |
| P2 | CSV의 CRLF·CR 줄바꿈 누락 | 인용 필드 내부 줄바꿈을 보존하면서 행 구분 처리 |
| P2 | Markdown 빈 셀 때문에 열 위치가 바뀜 | 내부 빈 셀 보존, 구분 행의 대시 검사 보완 |
| P2 | HTML의 직접 본문·인라인 태그 내용 누락 | 텍스트 노드와 인라인 내용을 읽고 중첩 목록 중복 방지 |
| P2 | PDF·OCR 정렬의 허용 오차 비교가 정렬 규약을 위반 | 페이지·좌표를 기준으로 일관되게 비교 |
| P2 | PDF 래스터화가 실패해도 경고 없이 OCR 누락 | 원문 텍스트를 유지하고 페이지 위치가 있는 자원 제한 경고 반환 |
| P2 | 시작 인덱스가 0이 아닌 `Data` 조각을 잘못 읽을 가능성 | 공개 입력 경계에서 데이터 인덱스 정규화 |
| P2 | 생성 후 동시성 옵션을 0으로 바꾸면 배치 결과 누락 | 실행 시 최소 한 개의 작업을 배정 |
| P2 | HWP 표의 대체 행 번호를 UInt16으로 변환할 때 범위 초과 가능성 | 인덱스를 Int로 유지 |

## 코드 정리

- `DocumentTextParser`는 91줄의 조정자로 유지하고 중복된 형식별 구현을 제거했다.
- CSV·구조화 텍스트·Markdown·HTML·참조 이미지·XML delegate를 각각 분리했다.
- 테스트는 텍스트·컨테이너·이미지·배치 및 취소·회귀·ZIP 검증으로 분리했다.
- 자체 생성 Office·HWPX XML과 이미지·PDF 생성 코드를 테스트 assertion에서 분리했다.
- 불필요한 import와 도달하지 않는 분기를 제거하고 내부 helper 접근 범위를 줄였다.
- SwiftLint 규칙을 완화하거나 비활성화하지 않았다.

## 검증

아래 명령으로 테스트 25개, 앱 빌드, 엄격 린트를 확인했다.
테스트는 기존 fixture와 자체 생성한 데이터만 사용하며 외부 문서를 추가하지 않는다.

```sh

  -destination 'platform=iOS Simulator,id=46BECA1F-89C4-42E2-B9DD-5F6CB316E62B' \

  -destination 'generic/platform=iOS Simulator'

```

추가 검증은 CRLF CSV, Markdown 빈 셀과 표 위치, HTML fragment와 중첩 목록,
이미지 실패 후 본문 보존, 결과 순번, ZIP 뒤쪽의 항목 식별, 문자열 위장·중복 항목·
절대 경로·항목 수 제한·잘린 ZIP 거부, 배치 종료 이벤트, 취소, 메인 스레드 이탈,
Data 조각, Office 임시 디렉터리 정리, PDF 페이지 순서와 래스터화 제한을 포함한다.

## 1차 리뷰 시점의 남은 제약과 미검증 항목

이 리뷰와 테스트 통과가 모든 형식의 완전한 추출을 증명하지는 않는다.

- 구형 Office의 잘못된 ZIP 거절은 수정했지만 DOC·XLS·PPT와 바이너리 HWP의
  실제 문서에서 본문·표·삽입 이미지를 모두 추출하는 검증은 남아 있다.
- PDF는 본문과 페이지 전체 OCR을 사용한다. 전용 표 구조 복원과 개별 삽입 이미지의
  원본 앵커 추출은 구현되어 있지 않다.
- TIFF는 첫 이미지 프레임만 처리한다. 다중 프레임 추출은 남아 있다.
- RTF는 텍스트 중심이며, 형식별 표·이미지 추출 범위는 기존 지원 문서의 제약을 따른다.
- 동기 Vision·서드파티 호출의 실행 중간을 강제로 중단하지 않는다.
  호출 전후와 페이지·이미지 경계에서 취소를 확인한다.
- ZIP 검사는 메타데이터와 선언된 크기 기준이다. 악성 압축 코퍼스 전체에 대한 검증,
  실기기 최대 메모리·처리 시간 측정, LGPL 배포 조건 점검은 이번 리뷰의 완료 항목이 아니다.
